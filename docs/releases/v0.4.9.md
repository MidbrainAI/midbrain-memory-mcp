# midbrain-memory-mcp v0.4.9

## TLDR

v0.4.9 completes the NanoClaw capture-reliability work from issues #51–#53,
adds cross-client episodic scoping metadata, and identifies package/client
traffic through the backend-supported `X-Midbrain-User-Agent` header.

- Existing and new NanoClaw groups capture as `nanoclaw`; ordinary Claude Code
  hosts remain `claude`.
- A cold NanoClaw wake preserves its opening user message and completed
  assistant response through durable state, bounded key resolution, and a
  binding-scoped recovery spool.
- Failed episodic captures drain once per boot through bounded, paced,
  binding-scoped, WAF-aware recovery instead of replaying on every hook.
- OpenCode, Claude Code, Codex, Hermes, and NanoClaw captures include optional
  privacy-normalized `cwd` and verbatim nonblank `session_id` metadata.
- Authenticated memory and account requests report package version and resolved
  client identity in `X-Midbrain-User-Agent`.
- Breaking changes: none.

## Overview

This release contains the complete delta since v0.4.8: PRs #54–#56 close the
three NanoClaw capture and recovery failures tracked as issues #51–#53, PR #57
adds episodic client/cwd/session metadata parity, and PR #58 adds package and
client request identity.

The NanoClaw work is intentionally narrow. It activates only for positively
identified NanoClaw topology or an explicit state-directory override. Normal
host installs preserve their existing paths, labels, credential precedence,
and capture behavior.

## Existing NanoClaw Group Migration (issue #51)

Pre-v0.4.8 NanoClaw groups may not have the durable capture-client marker that
newer installs use. Startup now positively identifies the mounted NanoClaw
topology and matching legacy MidBrain signals, then publishes the missing
`nanoclaw` marker before MCP readiness.

Marker creation is absence-only, race-safe, and mode `0600`. Existing files
and non-regular targets are preserved without content reads. Plain Claude Code
hosts do not match the NanoClaw topology and remain labeled `claude`.

## Cold NanoClaw Opener Recovery (issue #52)

NanoClaw starts disposable containers whose hook children do not inherit the
MCP server environment. On a cold wake, the first hook could therefore run
before its key or shim became available.

v0.4.9 relocates MidBrain-owned shared state to NanoClaw's durable Claude mount,
prepares positively owned capture state before readiness, and applies a bounded
NanoClaw-only key wait. If the exact no-key window still expires, the capture
is written to a binding-scoped recovery spool and replayed after authenticated
startup instead of being dropped.

The spool preserves duplicate occurrences, malformed or torn evidence,
concurrent appends, binding changes, and failed or rate-limited survivors.
Recovery is deliberately at-least-once rather than falsely claiming
exactly-once delivery.

## Disciplined Offline Cache Recovery (issue #53)

Successful hooks no longer replay the offline backlog. A server boot performs
one finite, paced drain for the currently authenticated host/key/agent binding.
Other opaque binding buckets remain untouched.

Rate limits and WAF-shaped failures publish a cache-wide cooldown before the
binding-local pass completes. Finite boot batches retain their unattempted tail,
and malformed, torn, concurrently appended, or uncertain bytes remain durable.
There is no expiry, quarantine, or permanent per-entry retry cap.

## Episodic Capture Metadata

Direct capture and recovery paths now share one metadata builder across
OpenCode, Claude Code, Codex, Hermes, and NanoClaw. Captures may include:

- the resolved client label;
- a privacy-normalized working directory;
- the client's nonblank session identifier, preserved verbatim.

Foreign usernames are removed from recognized POSIX, Windows, mounted, nested,
and UNC home-directory forms. Usernames are not added to request telemetry.

## Package and Client Request Identity

Every authenticated memory and account API request now sends
`X-Midbrain-User-Agent` with `midbrain-memory-mcp/0.4.9` and the resolved client
identity. NanoClaw requests report `nanoclaw`; ordinary Claude Code requests
report `claude`.

The custom header does not replace the runtime's standard `User-Agent` and
does not contain credentials, paths, session IDs, usernames, or memory content.
The relocated OpenCode bundle receives the same package version at build time.

## Compatibility and Operational Notes

- No MCP tools, bins, configuration formats, or credential locations were
  removed or renamed.
- `MIDBRAIN_STATE_DIR` remains opt-in outside the NanoClaw skill.
- `MIDBRAIN_SIMULATE_OFFLINE=1` remains a process-scoped diagnostic control;
  installers do not persist it.
- Recovery paths preserve the metadata attached to the original capture.
- Dependencies and the lockfile dependency graph are unchanged from v0.4.8.

## Testing

Release verification included:

- the canonical build, lint, Vitest, pinned-spec, documentation, and copied
  topology isolation gates;
- focused PR #54–#58 integration and recovery suites;
- package-content, forbidden-file, version, entrypoint, relocated-bundle, and
  dependency/lock-drift checks;
- publication of the exact tarball to an isolated loopback registry, followed
  by isolated global-install and npx execution from that registry;
- live behavioral parity for OpenCode, Claude Code, Codex, and Hermes;
- real WhatsApp NanoClaw cold wakes proving one user and one completed assistant
  capture per turn with `client=nanoclaw`, `/workspace/agent`, and a shared
  nonblank session ID;
- a real process-scoped offline fault proving retention, one boot-time drain,
  an empty final cache, and no duplicate recovered row;
- end-to-end request delivery plus programmatic coverage for
  `X-Midbrain-User-Agent`.

The host setup was restored after validation, and no test-only routing, state,
environment flag, shim, prefix, cache, or tarball remained active.
