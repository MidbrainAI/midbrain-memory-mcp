# v0.4.8 Light Notes

v0.4.8 is first and foremost an incident repair: v0.4.7's hook migration
moved Claude Code capture to a stable shim and dropped the inline API-key
prefix that containerized NanoClaw installs relied on, silently breaking
episodic capture in that topology. The MCP server now persists its
environment key to the global key file at startup — absence-only, atomic,
and guarded against self-hosted origin mismatches and scope promotion — so
hook children authenticate without environment passthrough. Because NanoClaw
runs `midbrain-memory-mcp@latest`, broken installs self-heal on the first
fresh container after updating, with no user action.

Around that fix, the release hardens credential handling end to end: all key
writes flow through one guarded atomic writer, the installer can no longer
promote credentials across scopes, and the MCP server and capture hooks now
resolve the API host identically so self-hosted configurations cannot split
across origins.

Two additions round it out: an account-management keystore for storing and
switching between multiple account credentials (deliberately never consulted
by capture), and a `memory_diagnostics` MCP tool that turns silent
authentication and capture failures into visible, explained ones. NanoClaw
captures can also now carry an accurate `nanoclaw` client label via a
validated, fail-open marker file written by the NanoClaw skill.

Capture restoration and labeling were validated live on a production
NanoClaw group before release.

Breaking changes: none.
