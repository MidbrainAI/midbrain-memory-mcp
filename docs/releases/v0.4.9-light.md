# v0.4.9 Light Notes

v0.4.9 completes the NanoClaw reliability work from issues #51–#53. Existing
groups migrate to the correct `nanoclaw` capture label before MCP readiness,
and ordinary Claude Code hosts remain `claude`. A cold NanoClaw wake now keeps
its opening user message and completed assistant response through durable
MidBrain state, bounded key resolution, and a binding-scoped recovery spool.

Offline capture recovery is also disciplined. Failed episodic writes remain
cached, then drain in one bounded, paced, WAF-aware pass at boot instead of
replaying the backlog from every successful hook. Recovery is binding-scoped
and deliberately at-least-once: ambiguous or malformed evidence is retained
rather than silently discarded.

Every supported client now sends optional episodic `cwd` and `session_id`
metadata. Home-directory paths are privacy-normalized across POSIX, Windows,
mounted, and UNC forms. Authenticated API requests also carry
`X-Midbrain-User-Agent` with the package version and resolved client identity,
including accurate Claude versus NanoClaw labeling.

The exact packed candidate passed the repository checks, isolated package
installation and npx verification, and live behavioral parity across
OpenCode, Claude Code, Codex, Hermes, and NanoClaw. NanoClaw validation used
real WhatsApp cold wakes and a real process-scoped offline recovery turn.

Breaking changes: none.
