# v0.4.10 Light Notes

v0.4.10 closes the final legacy NanoClaw cold-start gap. An untouched group
that still carries the historical v0.4.8 Claude hook topology can lose its
opening user message when that old shim fails before startup self-repair. The
assistant Stop hook can now recover that opener only when the trusted Claude
transcript proves the exact owned failure and binds it to the current NanoClaw
session, working directory, assistant response, and message ancestry.

The recovery path is intentionally narrow. It creates one terminal receipt,
makes at most one recovered-user POST attempt, and never places that user row
in the spool or offline cache. Normal assistant capture continues even if
recovery cannot run. Already-migrated NanoClaw groups and ordinary Claude Code
hosts keep their existing behavior.

MCP reads are more predictable too. `grep` now preserves semantic and episodic
lexical matches by default, supports an optional memory-type filter, and gives
mixed API result shapes intentional labels. `read_file` preserves a real GET
404 so missing semantic files return the existing friendly response instead of
being retried with POST.

No MCP tools, bins, configuration formats, dependencies, or credential
locations changed. Breaking changes: none.
