# midbrain-memory-mcp v0.4.7

## TLDR

v0.4.7 adds first-class Hermes Agent support, makes automatic repair safe
across temporary and cached launch paths, and installs proactive MidBrain
memory rules across every supported client.

- Hermes Agent now has supported detection, YAML MCP configuration, stable
  capture hooks, project scoping, installer integration, and user/assistant
  episodic capture.
- Automatic repair cannot persist a temporary worktree, `/private/tmp`, or
  npx-cache package path into durable client configuration.
- Codex, OpenCode, Claude Code, Hermes, and NanoClaw receive proactive
  memory-first rules with adapters for each client's tool-loading behavior.
- Global and project rule updates preserve custom or uncertain user hardening.
- `--no-rules` remains available for users who manage instructions manually.
- Breaking changes: None.

## Overview

This release combines the complete unreleased delta from v0.4.6: Hermes client
support from PR #33, durable self-repair and path-safety work from PR #34, and
cross-client proactive memory rules from PR #35.

The common goal is durability. Hermes becomes a supported MidBrain client,
capture hooks and client configuration stop depending on volatile runtime
paths, and supported agents receive concise instructions for recalling useful
context before substantive work.

## Hermes Agent Support

Hermes Agent is now a first-class client alongside OpenCode, Claude Code,
Codex, and NanoClaw.

- Detection uses the active Hermes home and `config.yaml`.
- MCP configuration is written to Hermes' `mcp_servers` map.
- Project setup scopes the MCP entry with Hermes'
  `${TERMINAL_CWD}` expansion instead of creating an inactive
  `<project>/.hermes/config.yaml`.
- User prompts from `pre_llm_call` and assistant responses from
  `post_llm_call` are stored as episodic memories with Hermes client metadata.
- Capture runs through the stable `~/.midbrain/bin/hermes-hook` shim with
  role-only commands and 30-second timeouts.
- The YAML document editor preserves comments and key order on untouched
  nodes and fails closed when the active config cannot be parsed safely.
- Existing custom MCP command/argument choices, environment mappings, and
  distinct per-client credentials are preserved where supported.
- The installer never enables Hermes' security-sensitive hook auto-accept
  setting. Users remain responsible for hook approval, and an already-running
  gateway must be restarted after setup.

The published package now includes the Hermes adapter and capture runtime, adds
the `hermes` package keyword, and promotes `yaml` to a production dependency
for comment-preserving configuration edits.

## Durable Self-Repair and Path Safety

Earlier repair paths could accidentally write the location of the currently
running package into durable client configuration. That was unsafe for launches
from disposable worktrees, `/private/tmp`, or an npx cache that may later be
removed.

v0.4.7 changes repair around canonical, location-independent targets:

- Launches from temporary directories, linked worktrees, and CI skip automatic
  repair and emit one actionable stderr message.
- An npx-cache launch remains the canonical installed-package mode, but repair
  writes only stable local shims and
  `npx -y midbrain-memory-mcp@latest`—never the current cache path.
- Claude Code capture moves to the same stable-shim model already used by
  Codex and Hermes.
- Claude Code, Codex, and Hermes validate the stable shim's exact canonical
  body and executable mode, not only its existence.
- Hook ownership is boundary-anchored. MidBrain migrates only its own stable
  shim, known legacy capture paths, or exact package-dispatch commands;
  similarly named wrappers and user scripts survive.
- OpenCode cleanup removes only the closed list of legacy MidBrain artifacts.
  User-owned `plugins/clients` content and unrelated `midbrain-*` files are
  preserved.
- Explicit `--dev` installations are marked and pinned against automatic
  repair. Development runtimes do not propagate themselves into canonical
  configuration; a later explicit non-development install restores canonical
  state.
- Content-compared writes avoid unnecessary rewrites and mtime churn,
  preserving hook approvals on already-correct installations.

Cross-client convergence remains intentional: a durable MidBrain startup can
repair stale MidBrain-owned state for every detected client. That convergence
is restricted to canonical, positively owned, idempotent state and preserves
user-owned and marked development configuration.

## Proactive Memory Rules

Global installation and project setup now synchronize a compact managed
MidBrain rules block for detected clients:

- Codex: global and project `AGENTS.md`.
- OpenCode: global and project `AGENTS.md`.
- Claude Code: global and project `CLAUDE.md`.
- Hermes: active global `SOUL.md`; project setup prefers an existing
  `.hermes.md`, then an existing `HERMES.md`, and otherwise uses `AGENTS.md`
  without creating a shadowing Hermes-only file.
- NanoClaw: shared `container/CLAUDE.md` plus every existing group's writable
  `CLAUDE.local.md`; generated/composed group `CLAUDE.md` files are not edited.

All clients share the same behavioral core:

- recall relevant MidBrain context before substantive work;
- preserve exact request anchors and search one target per call;
- refine incomplete recall rather than treating one ranked miss as absence;
- use episodic, semantic, exact-match, file, and date surfaces appropriately;
- require direct evidence for current-state claims and prefer live state over
  memory;
- never infer missing memory or manually create memories.

Only the tool-loading adapter differs by client. Codex and OpenCode use their
visible/deferred MCP discovery path, Claude Code and NanoClaw use
`ToolSearch` plus `Read` when results are externalized, and Hermes uses its
`tool_search` → `tool_describe` → `tool_call` sequence.

## Safe Rule Migration

Rules are enclosed in a recognizable managed block so later installs can
update known generated versions safely.

- Exact current and known legacy generated blocks are replaced in place.
- Recognizable unsentinelled legacy rules are migrated.
- Custom or uncertain MidBrain hardening is preserved and receives the managed
  block alongside it instead of being overwritten.
- Unrelated instructions remain unchanged.
- Re-running setup is idempotent.
- `--no-rules` skips global and project rule writes for users who manage
  instruction files themselves.

## Compatibility and Operational Notes

- No MCP tools were removed or renamed.
- Existing key-resolution and shared-versus-per-client credential behavior
  remains compatible.
- Existing Claude Code hooks migrate to the stable `claude-hook` command.
  This changes the command identity once; user hooks are preserved.
- Existing unmarked development hook entries from releases before v0.4.7 may
  migrate to canonical state during repair. Re-run `install --dev` to create
  explicitly marked development state.
- Hermes hook consent stays user-owned. Non-interactive Hermes environments
  may require user-configured approval behavior.
- Native Windows behavior has automated structural and real Windows test
  coverage from the repair work, while live provider verification for the
  final Hermes integration was performed on macOS.

## Retrieval Follow-up

Production validation across Codex, Claude Code, OpenCode, Hermes, and NanoClaw
confirmed MCP loading and live calls for every client. Ordinary proactive recall
also improved across the supported clients.

Exact retrieval in a noisy memory corpus still showed some prompt-sensitive
variance. A follow-up patch will harden that retrieval guidance. This is a
quality refinement to the generated instructions; it does not indicate an MCP
loading, episodic capture, installer, or configuration-safety failure.
